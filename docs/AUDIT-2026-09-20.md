# Security audit of the Zipher codebase — 2026-09-20

Read-only source audit of `atmospherelabs-dev/zipher-app` at the time of forking. Three parallel
reviewers (key custody + policy, AI-agent/MCP surface, network egress + supply chain) read the Rust
crates on `main` at `eced13d` (2026-06-08). Nothing was built or executed. Findings marked
**CONFIRMED** were traced end to end in code by the reviewer and the three most consequential
were re-read by the lead. Line numbers refer to `main` at `eced13d` unless stated.

This is the reason the fork is based on `feat/ironwood` (`2e7ccd3`, 2026-09-11) and not `main`.

## Upstream's own findings, for context

Two audits already live in the repo and were read in full:

- `docs/wallet-security-audit-2026-05-18.md` — 9 High, 8 Medium, mostly mobile. Agent-relevant:
  H8 empty vault passphrases allowed by default; H9 `serve` bound to 0.0.0.0 and accepted any
  payment header without a CipherPay key; M1 session bearer tokens in plaintext; M5 audit log
  plaintext.
- `docs/security-review-2026-09-10.md` + `docs/security-remediation-2026-09-10.md` (ironwood only)
  — S1–S9. Agent-relevant and **fixed on ironwood**: S3 MCP clients could unlock themselves and
  self-approve (tools `wallet_unlock` and `approve_send` removed); S4 daily cap omitted successful
  payments (durable reservations, fail closed on corrupt policy); Polymarket agent order signing
  removed; MCP confirmations bound to an unpredictable `proposal_id`.

## Why `main` is unusable as a base (VERIFIED)

- `main` does not compile as checked out: `engine::send::propose_send` takes 5 arguments
  (`send.rs:120-126`), every CLI and MCP caller passes 4 (`mcp-server/main.rs:447` and 9 others).
- Zcash mainnet was at height 3,490,545 on the audit date; the repo records Ironwood activation at
  3,428,143. `main` predates the NU6.3 upgrade and cannot sync mainnet.
- `main` lacks every S1–S9 fix above.

### Low / Info

- `serve` defaults are sane on `main` (127.0.0.1:8402, empty CORS allowlist, refuses unverified without `--demo-accept-unverified`), but has no auth or rate limit once `--listen 0.0.0.0` is passed. Daemon Unix socket is 0600 with no further auth.
- Wallet DB (UFVK, notes, memos, history) is plaintext on headless surfaces: SQLCipher key passed as `None`. Not the seed, but a complete privacy loss of history.
- The OpenClaw skill still references `ZIPHER_SEED` in the agent's environment; the CLI reads only the OWS vault. Stale and normalises the seed living in the agent's env.
- `docs/mcp-system-prompt.md` tells the model to trade autonomously with "never exceed the policy" as the only brake and cites tools that do not exist.
- No `get_policy`/`set_policy` MCP tools exist despite `npm/mcp.json` and README claiming them.
- History secret scan (gitleaks, 1,458 commits): 21 hits, none a live credential. CocoaPods checksums plus the NEAR Intents partner JWT (public affiliate key, expires 2027-02).

## What is done well (keep it)

- Amounts are `u64` end to end; floats, negatives and NaN cannot reach `check_proposal`.
- On every ZEC path the policy check runs before the seed is read or the USK derived; seed is `SecretString`; seed bytes zeroised after USK derivation; no key material in any log line (grep-verified); MCP disables core dumps and ptrace.
- Two-step propose/confirm with deterministic error codes and a persistent audit row on every spend path.
- Network-sourced destinations (x402 `payTo`, MPP recipient, swap deposit address) do pass through the allowlist.
- Vault crypto is sound where used: scrypt N=2^16 + AES-256-GCM, fresh salt and nonce, derived key zeroised.
- Sapling params download is SHA-256 pinned.
- Ironwood adds durable spend reservations in SQLite immediate transactions and binds MCP confirmations to unpredictable proposal IDs.
